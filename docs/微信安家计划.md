## 与旧架构的差异

| 维度 | 旧（Windows + QQ） | 新（Mac + 微信） |
|---|---|---|
| 聊天平台 | NapCat + QQ（云端 Docker） | **个人微信 `weixin_oc` 适配器**（AstrBot 内置，腾讯官方 openclaw-weixin/ClawBot 接口，扫码 + 长轮询，无 webhook、无 Docker） |
| 部署形态 | Docker Compose（2C4G） | **uv 原生 + systemd**，尽量少运行时 |
| 主力工作机 | Windows（雷电模拟器/PhoneMCP/B 站 MCP/桌面快捷方式） | **本 Mac（96G 内存）**：重媒体（TTS、ffmpeg 抽帧、浏览器）尽量放 Mac，反向接入 VPS |
| LLM 供给 | 付费 API（DeepSeek/百炼） | **agy 额度投喂**：AstrBot provider 指向同机 `agy-bridge`（`100.102.85.99:8788/v1`），按可用 quota 百分比节流（5h/周额度机制） |
| 嵌入 | 硅基流动 bge-m3 托管 | 不变（用户确认有 API key；免费额度情况待实测） |
| QQ / 群聊 | 核心玩法 | **后置**。微信 ClawBot 官方只支持私聊（`chatTypes: ["direct"]`），群聊是 open issue；群玩法要么留 QQ（需 Docker+NapCat，后置再议）要么放弃 |

## VPS 体检结论（2026-11-04 实测）

- Debian 13 trixie x86_64，2 核，1.9GiB 内存（**可用约 1.3GiB，无 swap**），磁盘余 44GiB。
- 已装 Python 3.13.5 / Node 20；**无 Docker（本计划也不需要）**、无 Java、无 ffmpeg。
- 常驻服务：agy-bridge(:8788)、agy-tunnel、artalk、nginx、postgres17、xray、easytier、hateppt、tailscale、cloudflared，已占约 0.6GiB。
- 内存预算：AstrBot 原生 300–450MB + wxclawbot 桥峰值 ~50MB + 按需 ffmpeg ~200MB → 峰值 < 0.9GiB，**可行但紧**；实施前加 **2G swapfile** 兜底。
- 磁盘：venv ~2GB + 数据/缓存，充裕。

## 微信通路的已知限制（验收边界，必须如实标注）

1. **不能主动发起会话**：ClawBot 只能回复既有会话。定时提醒/主动找主人走社区 `wxclawbot-cli`（复用 AstrBot 保存的 iLink token）。
2. **AstrBot cron `misfire_grace_time=30s` 硬编码**：经 CLI 发送的长任务会被 APScheduler 静默丢弃（社区实测 missed 36s 即跳过）。需进 `deploy/patches/`，升级后重新核对。
3. **语音条发不出**（语音：收=是/云端自动转文本，发=否）。TTS 在微信上降级为发音频文件；qwen3-asr 听写链路在微信侧**不再需要**（收语音自动变文字）。
4. **无群聊**（见上表）。记忆隔离仍按会话 `session` 作用域，但 v0.x 只有主人私聊一个真实作用域。
5. agy 每轮延迟 **25–90s**、每轮自带 5–8k token 系统开销。聊天节奏、超时（≥900s 客户端超时）、降级模型策略都围绕这两条设计。Google 侧偶发 503 容量抖动（bridge 已按经验处理）。
6. 手机微信版本要求：iOS ≥ 8.0.70 / Android ≥ 8.0.69，PC ≥ 4.1.8.67 且手动装 ClawBot 插件。

## 阶段计划（每阶段独立验收，默认开关关闭）

### V01 · VPS 原生 AstrBot + 微信私聊冒烟
- uv 安装 AstrBot（`--python 3.12`），systemd 单元，WebUI 绑 127.0.0.1:6185，走 SSH 隧道管理。
- 2G swapfile；`ffmpeg` 先不装（V03 决定放 Mac 还是 VPS）。
- 主人扫码登录个人微信。
- **验收**：微信私聊发一句话，AstrBot 能回（人格未接，回显即可）；`systemctl` 重启后登录态保持；离线测试跑通。
- 边界：无真实 LLM 供给（占位 provider），无记忆。

### V02 · agy 裸投喂
- AstrBot provider 指向 agy-bridge（`/v1/models`、`chat/completions`，超时 ≥900s）；导入 `persona/大肥鱼-人格.md`。
- **验收**：真实对话若干轮，延迟与失败路径（503/429）有日志证据。
- 边界：无额度节流，烧多少算多少——**故意留到 V06 治理**；先建立额度基线观测。

### V03 · Mac 重媒体服务
- Mac 起小型只读服务：TTS（百炼 key 留在 Mac）、ffmpeg 抽帧/切音频 worker；经既有 tailscale/SSH 反向接线供 VPS 调用。
- 观测台（memory_observatory）在 Mac 常驻，只读拉 VPS 快照（建 `~/.dafeiyu-admin/host` + 密钥）。
- **验收**：Mac 服务健康检查 + VPS 侧一次真实调用；观测台真实模式接入新数据源。
- 边界：TTS 在微信以文件形式送达；语音条留待 QQ 后置。

### V04 · LivingMemory + 硅基流动嵌入
- livingmemory 插件 + `apply_sf_embedding` 风格切换脚本（key 由 Mac 侧管理）；`session` 作用域只挂主人私聊。
- 免费额度实测：若 bge-m3 计费与预期不符，回退讨论本地小嵌入模型。
- **验收**：跨会话召回冒烟 + 观测台来源面板显示真实记忆；不改变衰减策略。

### V05 · 主动联系（cron + wxclawbot-cli）
- `deploy/patches/` 新增 cron misfire 补丁（30→300s）与 weixin_oc 发送桥；沿用 proactive_chat 额度/间隔/让位设计（`CONTACT_V01` 语义）。
- **验收**：一条定时消息真实送达微信；失败保留日志且不误报成功。
- 边界：主动消息仍受"既有会话"约束——首次必须由主人先开聊。

### V06 · agy 额度 governor
- 调研 headless agy 是否暴露 5h/周额度百分比（CLI/本地 sqlite/日志）；设计按百分比投喂：高额度放宽并发/模型档位，低额度降级（flash-high→medium→low）或排队/429。
- 落点：优先做进 agy-bridge 中间件（repo 文化：观测在 bridge，行动在插件提议）。
- **验收**：离线模拟额度曲线下的节流决策表；真实观察一周再放开自动调节。

### V07 · B 站自主生活移植（可选后置）
- `astrbot_plugin_bili_activity` 的审批/预算/账本框架平台无关，可移植到微信私聊审批；B 站 MCP 服务从 Windows 脚本改为 Mac 原生（Python 3.12+，ffmpeg 本机）。
- 边界：PhoneMCP/雷电模拟器整条线**作废**，不再随仓库主推。
